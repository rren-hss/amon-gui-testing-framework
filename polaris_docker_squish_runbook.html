Polaris Docker + Squish Runbook

Platform: Ubuntu 22.04.5 LTS
Polaris repository: ~/Desktop/polaris-v3
Squish: 9.2.2 for Qt 6.11.x
Last updated: August 21, 2026

This document records how the Polaris Docker system was started and built, how Squish was installed and exposed to the Docker containers, and how the Cart and Assistant GUIs were launched as attachable AUTs.

1. Final architecture

Component Container Host Squish endpoint AUT endpoint inside container
Cart GUI docker-cart 127.0.0.1:14322 localhost:9999
Assistant GUI docker-cart 127.0.0.1:14322 localhost:9997
Surgeon GUI docker-cockpit 127.0.0.1:24322 localhost:9998

The Squish IDE connects to the published host port. Docker forwards that connection to port 4322 on the appropriate container. The container’s Squish Server then attaches to an AUT launched through startaut.

Squish IDE
  ├── 127.0.0.1:14322 → docker-cart:4322
  │     ├── cart_gui      → startaut:9999
  │     └── assistant_gui → startaut:9997
  └── 127.0.0.1:24322 → docker-cockpit:4322
        └── surgeon_gui   → startaut:9998

Verified state

  • Docker, Docker Compose, and NVIDIA GPU access work.
  • All Polaris packages build successfully.
  • Polaris GUIs run in the four Compose containers.
  • Squish 9.2.2 for Qt 6.11.x is installed on the host.
  • Cart and Cockpit Squish Server ports are published.
  • Cart, Assistant, and Surgeon are registered as attachable AUT names.
  • Cart and Assistant were verified listening on ports 9999 and 9997 after rebuilding polaris_scripts.
  • The Surgeon launch script still needs the same startaut modification before its endpoint will listen on 9998.

2. Host and Docker preparation

Verify the host:

cat /etc/os-release | grep -E '^(NAME|VERSION|VERSION_CODENAME)='
docker --version
docker compose version
systemctl is-active docker
df -h /

The working host used Ubuntu 22.04.5, Docker 29.7.2, and Docker Compose v5.5.0.

Docker permission fix

The initial hello-world test failed because the user could not access /var/run/docker.sock. The account was added to the Docker group:

sudo usermod -aG docker "$USER"

Log out and back in, or reboot, before checking:

id -nG
docker run --rm hello-world

The docker group grants root-equivalent control through Docker. Only trusted users should belong to it.

Repository and environment

cd ~/Desktop/polaris-v3
git status
docker compose config --services

export DOCKER_UID="$(id -u)"
export DOCKER_GID="$(id -g)"
xhost +local:docker

The repository defines cart, cockpit, perception, and techpc services.

NVIDIA Container Toolkit

The first make up failed because Docker could not select the NVIDIA runtime. After installing NVIDIA Container Toolkit:

sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker

Verify GPU access:

docker run --rm --gpus all \
  nvidia/cuda:13.1.0-base-ubuntu22.04 \
  nvidia-smi

3. Start and build the Polaris containers

Start all services:

cd ~/Desktop/polaris-v3
make up
docker compose ps

The expected container names are:

docker-cart
docker-cockpit
docker-perception
docker-techpc

Build Polaris

Enter the Cart container:

make shell cart

Inside the container:

source /opt/ros/humble/setup.bash
source /opt/rti_connext_dds-7.3.0/resource/scripts/rtisetenv_x64Linux4gcc7.3.0.bash

colcon build --event-handlers console_direct+

The first full build exhausted resources while compiling surgeon_gui. It was recovered with sequential builds:

export CMAKE_BUILD_PARALLEL_LEVEL=1
colcon build \
  --packages-select surgeon_gui \
  --executor sequential \
  --event-handlers console_direct+

export CMAKE_BUILD_PARALLEL_LEVEL=2
colcon build \
  --executor sequential \
  --event-handlers console_direct+

5. Install the correct Squish build

The original local Squish installation targeted Qt 6.8:

~/squish-for-qt-9.2.2_68x

The Docker Polaris GUIs use Qt 6.11.1:

docker exec docker-cart bash -lc '
  qtpaths6 --qt-version 2>/dev/null || qmake6 -query QT_VERSION
'

docker exec docker-cart bash -lc '
  ldd /workspace/install/cart_gui/bin/appCart |
  grep -E "Qt6(Core|Quick|Qml)"
'

Squish’s Qt wrapper must match the AUT’s Qt version. A separate Qt 6.11 build was therefore installed from:

~/Downloads/squish-9.2.2-qt611x-linux64.run

Install it to a separate directory so the Qt 6.8 installation is not overwritten:

~/squish-for-qt-9.2.2_611x

For an interactive installation:

chmod +x ~/Downloads/squish-9.2.2-qt611x-linux64.run
~/Downloads/squish-9.2.2-qt611x-linux64.run

Use the existing company floating-license configuration when requested. Verify the installation:

ls -l \
  ~/squish-for-qt-9.2.2_611x/bin/startaut \
  ~/squish-for-qt-9.2.2_611x/bin/squishserver \
  ~/squish-for-qt-9.2.2_611x/bin/squishrunner

~/squish-for-qt-9.2.2_611x/bin/squishserver --version

6. Mount Squish and publish the servers

Create ~/Desktop/polaris-v3/docker-compose.override.yaml:

services:
  cart:
    volumes:
      - /home/rren/squish-for-qt-9.2.2_611x:/horizon/thirdparty/squish/9.2.2:ro
    ports:
      - "127.0.0.1:14322:4322"

  cockpit:
    volumes:
      - /home/rren/squish-for-qt-9.2.2_611x:/horizon/thirdparty/squish/9.2.2:ro
    ports:
      - "127.0.0.1:24322:4322"

Validate and recreate only the affected containers:

docker compose config --quiet
echo $?

docker compose up -d --force-recreate cart cockpit
docker compose ps

Verify Squish is visible inside both containers:

docker exec docker-cart \
  /horizon/thirdparty/squish/9.2.2/bin/squishserver --version

docker exec docker-cockpit \
  /horizon/thirdparty/squish/9.2.2/bin/squishserver --version

7. Configure allowed hosts

Determine Docker’s bridge gateway:

docker inspect \
  --format='{{range .NetworkSettings.Networks}}{{.Gateway}}{{end}}' \
  docker-cart

The gateway in this setup was 172.18.0.1.

Squish reads allowed client addresses from /etc/squishserverrc. Create it in both containers:

docker exec -u 0 docker-cart sh -c \
  'printf "%s\n" "ALLOWED_HOSTS=172.18.0.1" > /etc/squishserverrc'

docker exec -u 0 docker-cockpit sh -c \
  'printf "%s\n" "ALLOWED_HOSTS=172.18.0.1" > /etc/squishserverrc'

Important distinctions:

  • /etc/squishserverrc controls ALLOWED_HOSTS and the listening port.
  • $HOME/.squish/ver1/server.ini stores AUT registrations and other Squish Server settings.
  • --configfile points to a structured server.ini; it must not point to a plain ALLOWED_HOSTS=... file.

/etc/squishserverrc is currently created inside each container and will be lost if that container is recreated. Re-run this step after recreation, or later add a persistent bind mount for the file.

8. Start the Squish Servers

Start one server in each container:

docker exec -u 1000:1000 docker-cart \
  /horizon/thirdparty/squish/9.2.2/bin/squishserver \
  --port 4322 \
  --daemon \
  --logfile /home/rren/.squish/squishserver-4322.log

docker exec -u 1000:1000 docker-cockpit \
  /horizon/thirdparty/squish/9.2.2/bin/squishserver \
  --port 4322 \
  --daemon \
  --logfile /home/rren/.squish/squishserver-4322.log

Check the host-side TCP forwarding:

nc -zv 127.0.0.1 14322
nc -zv 127.0.0.1 24322

Check the real Squish protocol:

~/squish-for-qt-9.2.2_611x/bin/squishrunner \
  --host 127.0.0.1 --port 14322 \
  --info attachableApplications

~/squish-for-qt-9.2.2_611x/bin/squishrunner \
  --host 127.0.0.1 --port 24322 \
  --info attachableApplications

An empty result without an error means the server connection works but no AUT has been registered yet.

9. Register the attachable AUTs

Register from the host through the remote Squish Servers:

# Cart container
~/squish-for-qt-9.2.2_611x/bin/squishrunner \
  --host 127.0.0.1 --port 14322 \
  --config addAttachableAUT cart_gui localhost:9999

~/squish-for-qt-9.2.2_611x/bin/squishrunner \
  --host 127.0.0.1 --port 14322 \
  --config addAttachableAUT assistant_gui localhost:9997

# Cockpit container
~/squish-for-qt-9.2.2_611x/bin/squishrunner \
  --host 127.0.0.1 --port 24322 \
  --config addAttachableAUT surgeon_gui localhost:9998

Verify:

~/squish-for-qt-9.2.2_611x/bin/squishrunner \
  --host 127.0.0.1 --port 14322 \
  --info attachableApplications

~/squish-for-qt-9.2.2_611x/bin/squishrunner \
  --host 127.0.0.1 --port 24322 \
  --info attachableApplications

Expected mappings:

assistant_gui  localhost:9997
cart_gui       localhost:9999
surgeon_gui    localhost:9998

These mappings are stored under the persistent per-container /home volume.

10. Launch Cart and Assistant through startaut

Edit the source launcher:

cd ~/Desktop/polaris-v3
nano scripts/run_cart.bash

Replace the two direct GUI launches with:

squish_root="/horizon/thirdparty/squish/9.2.2"

launch "$squish_root/bin/startaut" \
    --verbose \
    --port=9999 \
    "$install_root/cart_gui/bin/appCart" \
    2> /home/rren/.squish/startaut-cart.log

launch "$squish_root/bin/startaut" \
    --verbose \
    --port=9997 \
    "$install_root/assistant_gui/bin/appAssist" \
    2> /home/rren/.squish/startaut-assistant.log

Critical: rebuild the installed launcher

make run cart executes:

/workspace/install/polaris_scripts/run_cart.bash

It does not execute scripts/run_cart.bash directly. Rebuild polaris_scripts after changing the source:

docker exec -it docker-cart docker-entrypoint.sh bash -c '
  source /opt/ros/humble/setup.bash
  source /opt/rti_connext_dds-7.3.0/resource/scripts/rtisetenv_x64Linux4gcc7.3.0.bash
  cd /workspace

  colcon build \
    --packages-select polaris_scripts \
    --event-handlers console_direct+
'

Verify the installed copy:

grep -n -A18 'squish_root' \
  install/polaris_scripts/run_cart.bash

Start Cart and Assistant:

make run cart

Leave that terminal running.

Verify the AUT endpoints

The container image does not include ss, so /proc/net/tcp* was used. Port values appear in hexadecimal:

  • 9997 = 270D
  • 9999 = 270F
docker exec docker-cart bash -lc \
  "grep -E ':(270D|270F) ' /proc/net/tcp /proc/net/tcp6 || true"

Two listening entries confirm that Cart and Assistant are ready for Squish attachment.

11. Correct runtime order

The shutdown() function in scripts/common.bash intentionally kills launched descendants and orphaned processes. Consequently, stopping make run cart can also kill a daemonized Squish Server in the same container.

For the current setup, use this order:

  1. Start make run cart and leave it running.
  2. Start or restart squishserver in docker-cart.
  3. Verify --info attachableApplications succeeds.
  4. Run the Squish test.
  5. Expect to restart squishserver after stopping and restarting make run cart.

Restart command:

docker exec -u 1000:1000 docker-cart \
  /horizon/thirdparty/squish/9.2.2/bin/squishserver \
  --port 4322 \
  --daemon \
  --logfile /home/rren/.squish/squishserver-4322.log

Confirm both the process and protocol:

docker exec docker-cart ps -ef | grep '[s]quishserver'

~/squish-for-qt-9.2.2_611x/bin/squishrunner \
  --host 127.0.0.1 --port 14322 \
  --info attachableApplications

An open Docker host port alone is not sufficient. If the internal server has been killed, Docker may still accept the host TCP connection and then report:

Peer closed the connection during handshake

12. Configure Squish IDE

Start the matching IDE:

~/squish-for-qt-9.2.2_611x/bin/ide/squishide

Open:

Edit → Preferences → Squish → Servers

Choose Add → Remote Server and create:

Name: docker-cart
Location: 127.0.0.1:14322

Select docker-cart, choose Set as Default, and apply the settings.

Do not replace the existing physical-system entries such as amon-cart or amon-cockpit.

For Cockpit, add another remote server later:

Name: docker-cockpit
Location: 127.0.0.1:24322

The Cart test attaches with:

def main():
    attachToApplication("cart_gui")

The Assistant test uses:

def main():
    attachToApplication("assistant_gui")

13. Troubleshooting reference

Peer closed the connection during handshake

Check whether the container’s Squish Server is actually running:

docker exec docker-cart ps -ef | grep '[s]quishserver'

If it is absent, restart it after make run cart is active.

TCP succeeds but Squish fails

nc -zv checks only that Docker accepts the TCP connection. Use this to test the Squish protocol:

~/squish-for-qt-9.2.2_611x/bin/squishrunner \
  --host 127.0.0.1 --port 14322 \
  --info attachableApplications

Remote address rejected

Check:

docker exec docker-cart cat /etc/squishserverrc
docker exec docker-cart tail -n 100 \
  /home/rren/.squish/squishserver-4322.log

The expected allowed host is the current Docker bridge gateway, which was 172.18.0.1 in this setup.

GUI launches but no AUT port appears

Check the startaut logs:

docker exec docker-cart sh -c '
  echo "=== CART ==="
  sed -n "1,160p" /home/rren/.squish/startaut-cart.log
  echo "=== ASSISTANT ==="
  sed -n "1,160p" /home/rren/.squish/startaut-assistant.log
'

Confirm that polaris_scripts was rebuilt and that the installed launcher—not only the source launcher—contains startaut.

Missing Polaris shared libraries during a manual test

If a manual startaut command reports a missing ROS or Polaris library, source the installed environment first:

docker exec -it docker-cart docker-entrypoint.sh bash -c '
  source /workspace/install/polaris_scripts/setup.bash

  exec /horizon/thirdparty/squish/9.2.2/bin/startaut \
    --verbose \
    --wrapper=Qt \
    --port=9999 \
    /workspace/install/cart_gui/bin/appCart
'

14. Shutdown and cleanup

  • Stop foreground make run ... commands with Ctrl+C.
  • Use docker compose stop to preserve containers and named home volumes.
  • Be careful with make down: the repository maps it to docker compose down -v --remove-orphans, which deletes named /home volumes.
  • Revoke X11 access when finished:
xhost -local:docker

15. Recommended follow-up improvements

The current setup works but still has two manual lifecycle steps. The next implementation should:

  1. Persist /etc/squishserverrc through a bind mount or container image layer.
  2. Start Squish Server as a tracked part of the Cart/Cockpit launcher or as a dedicated Compose service/process.
  3. Apply the same startaut pattern to scripts/run_cockpit.bash for surgeon_gui on port 9998.
  4. Rebuild polaris_scripts after modifying the Cockpit launcher.
  5. Add health checks for ports 4322, 9997, 9998, and 9999.
